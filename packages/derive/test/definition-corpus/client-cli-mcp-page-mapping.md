## Three unchecked multi-board presentation fixtures

The first owning Node run refused `MCP/input ordered true`, `MCP/routing members
false` and `MCP/routing members true` at all four inherited
`acts.commit/fulfill/fail/cancel.also.board` selections. These three original
fixtures change Counting commitments' singleton board to `many: true`, while
leaving those inherited `one: true` selections unchanged. The format-1 rule in
`validate/handlers.ts` requires `one: true` to select a type with `many: false`.
They are therefore not positive whole-definition validator inputs.

This is present in immutable original `f7b59bf92d1abe20300818ab109fa12df617c2e0`:
`declared-view-inputs.test.ts#fixture` changes board cardinality only for ordered
true; `declared-view-routing.test.ts#fixture` does so for both withMembers values.
Their comments explicitly limit the witnesses to scripted model/read/standing
ports and pre-sign/routing behavior, not native submission or authority.
`applicationCounterPacket2` starts from the exact Counting commitments export;
the lifted raw mutation bodies preserve the original expressions. The package
packer checks envelope/declaration references and presentation contracts rather
than calling the derive whole-definition validator. Successful packet packing
and scripted sessions did not establish positive Native declaration admission.

Only those three corpus rows are removed. The ordered-false input declaration
remains registered. Raw helper functions, all original MCP tests and assertions,
packet signatures/projection routing, validator rules and existing pins stay
unchanged. The original three failed results remain evidence of a mistaken
positive classification, not an extraction byte change. No validator relaxation
or rewritten owning fixture is used to make the corpus pass.
