# General creation, standing, timed and source-order definitions

These rows preserve the six owning test files' complete positive declarations.
The shared raw functions replace construction or mutation only; the existing
validators, judgments, histories, assertions and validation contexts stay at
their original test call sites. No test or validator was run for this mapping.

- `created-definitions`: base Desk, ordered direct digest pair, self/platform
  sends plus the unused digest-shaped rule, and the late child creation. These
  are successive states of the same mutable fixture. Shared mutations preserve
  that order and the original send references; each corpus factory rebuilds
  the preceding states before its named validation point.
- `creation-context`: the child literal, two renamed child declarations, the
  child whose genesis creates Rules, and the three actual parent argument sets
  (ordinary child/Lane, Rules-creating child/Lane, ordinary child/Membership).
  Each parent pins the exact corresponding child digest. Incoming malformed
  metadata/device grants and source-message substitutions are history/input
  negatives, not alternative definition bytes. Default profiles/options remain.
- `standing`: base platform data, whole capacity, removed counter default with
  explicit genesis initialization, zero maximum, and the non-genesis singleton.
  These preserve PROFILES and platform:true. Old Desk validation stays declared
  with omitted profiles/options. Unsafe standing products, malformed standing
  grammar, the same marked data without platform:true, and scopeEntries=5 are
  explicit invalid contexts and are excluded from the positive corpus.
- `timed`: default Lane, the two rule names ordered by UTF8 rather than UTF16,
  and the original JSON.parse declaration with own __proto__/constructor keys.
  The JSON text and parse operation are retained; object-literal rewriting
  would change own-property semantics. All use default profiles/options.
- `source-order`: baseline, explicit arrival, source-time field/effect, and
  the guard allowing only value one. The later act source-time mutation and
  three malformed order edits remain deliberately invalid and local.
- `source-order-reserved`: both source/arrival export forms under exact
  PIN_BOUNDS and the item-bound arrival form under platform:true. The later
  source-order item-bound combination remains a named validator refusal.

Request fields, actor/member identities, arrivals, clocks, corrupted state
views and entry/evidence alterations do not introduce additional declarations.
Equal bytes retain separate origin/context rows rather than being deduplicated.
This finite shard does not claim global corpus completeness or runtime results.
