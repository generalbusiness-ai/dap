# A post-deployment Durable Object rate read

RR-1 (request `d4cc718e`) adds `scripts/do-rate.mjs`. The script reads
Durable Object requests per minute per Worker from the Cloudflare GraphQL
analytics API. It replaces the planner's scratch rate script, so every
deployment ends with the same checked-in read.

## What the script reads

The script queries `durableObjectsInvocationsAdaptiveGroups` with
`scriptName_in` and groups by `datetimeMinute` and `scriptName`. It asks
for at most 10,000 groups. A reply at that limit splits the window in half
and reads each half again. A one-minute window at the limit fails, so the
script never reports a truncated reply.

## Arguments

- `--minutes N` reads the window that ends at the current minute.
  `--since` and `--until` give UTC times at minute precision instead;
  `--until` is exclusive. A window holds at most seven days.
- `--worker` names a Worker script and repeats. The default comes from the
  tracked configurations of `grow`, `lending`, `demo`, `artroom-scope` and
  `sandbox` in `scripts/deploy-config.mjs`: `dap-grow`, `dap-lending`,
  `dap-demo`, `artroom-scope` and `dap-application-sandbox`. These are the Workers
  that `deploy.mjs` deploys. The sandbox has no Durable Objects and reads
  zero.
- `--all` reads every Worker in the account that has Durable Object
  requests in the window, the busiest first. The query then names no
  Worker. A Worker outside the `deploy.mjs` list, such as
  `artroom-counting` at about 7,000 requests an hour, shows only here.
  `--all` and `--worker` exclude each other.
- `--token-file` names a file with a bare token or `KEY=value` lines with
  `CLOUDFLARE_ANALYTICS_TOKEN` or `CLOUDFLARE_API_TOKEN`. Without it, the
  script reads the `CLOUDFLARE_ANALYTICS_TOKEN` environment variable.
- `--account` gives the account ID. Without it, the script reads
  `CLOUDFLARE_ACCOUNT_ID` from the environment, then from the token file.
  The repository holds no account ID.
- `--baseline` names a JSON object of Worker name to a floor in requests
  per minute.

The script never prints the token. It replaces any token text in its output
and error messages.

## Output

The first line names the window. One line per minute follows, for example
`07:02Z dap-grow=55 dap-lending=0`, with zero for a Worker without
requests. The `total` line sums each Worker, and the `per-hour` line scales
each total to 60 minutes with one decimal. With a baseline, a minute over a
floor ends in ` above: dap-grow(55>40)`, and the `above-baseline` line
counts those minutes per Worker.

The script exits 0 on a report, 2 on bad arguments and 1 on an API
failure.

## Test

`scripts/do-rate.test.mjs` runs in the Node stage without network. It uses a
recorded reply with two Workers and a missing minute. It covers the zero
fill, the totals and per-hour lines, the baseline flag, an API `errors`
reply that exits 1 without token text, the row-limit split and its
one-minute failure, a `KEY=value` token file, bad arguments, and the
default Worker names.

`docs/operate-a-service.md` names the read as step 7 of a deployment, after
the smoke checks.
