# Read large diffs one file at a time

## A compact file list leads to the patch that matters

Use a small own renderer with plain source text, a factual comparison summary, and a collapsible header for each received file. Keep the path, patch counts, attribution, and **Collapsed** state visible when its body closes. Folding hides received content and marks nothing reviewed. One open file can hold a bounded scroll area, with an explicit scroll label. The first screen shows the file index without repeating commit IDs or paragraphs of comparison prose.

Its [collapsed key render](../2026-11-02-readable-diff-design/renders/truncated.png) keeps **Truncated** and the original omission visible after every file closes. These static HTML sources reuse the current card-frame CSS. Their read buttons stay inactive. Native disclosures exercise only local presentation.

Use unified rows at both 592 and 320 CSS pixels. Separate old and new gutters preserve coordinates. Addition and deletion signs supplement row fills, context stays quieter, and neutral hunk bands keep ranges apart from code. Restrained word emphasis locates a replacement within its own patch. It never assigns authorship. The final mockups use 12-pixel source text. File, context, and commit disclosures have at least 44-pixel targets.

Keep exact endpoints one **Commits** press away. A changed-base interdiff needs all four commits with their roles. Short IDs beside each mixed patch identify its own base and integration. Its two coordinate systems must never collapse into one confident integration-to-integration edit.

Separate three states. A counted **2 unchanged lines · collapsed** control expands two received rows locally. **Outside-hunk context not received** describes bytes absent from the answer. **Truncated** names an explicit omission and retains the server's `leftOut` words. Neither absent state is a local fold or a promise that another press can fetch a range.
