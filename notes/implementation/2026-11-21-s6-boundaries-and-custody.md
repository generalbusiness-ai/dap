## What changed

The CLI escapes control characters and direction controls in member-authored terminal text. Ordinary `dap clone` checks the consumed credential's remote against the recorded host, namespace, and repository name before it saves the remote or starts Git. The archive path retains its existing checks.

The room Worker sets `Cross-Origin-Opener-Policy: same-origin-allow-popups` for Page responses. The Artifacts member read mint verifies the binding's exact repository remote before minting and requires the reply to declare `scope: "read"`.

Workspace custody clears unread local plaintext at its recorded end. The alarm also handles pre-queue rows. A CLI join saves a terminal used or expired invitation refusal before discarding the private request. It retains requests with unknown outcomes, unverified acceptance, or an inactive inbox. After verified completion it records a cleanup marker before discarding the private request.

Counter keeps a recognized invitation fragment during enrollment. A failed join clears only the used fragment after the attempt settles. A successful join clears it after custody is saved. The captured invitation remains available for a retry in the current page, and unknown sent requests retain their existing Check and Continue custody. The helper preserves the path, query, history state, and newer or unrelated fragments.

## Decisions and reasons

The CLI uses a private decoded-text display boundary. It escapes C0, DEL, backslash, C1, bidirectional controls, and line separators without changing stored values. JSON rendering retains its existing framing. A mismatched ordinary clone remote stops before disclosure, storage, or Git; the refusal states that the single-use credential may already have been consumed.

Page's opener policy covers the page, redirect, assets, and refusals, including earlier Worker refusals. It does not change `/oauth/authorize`. Planner ruling `be8d9c03d47a5abde32f96e0403293112d600222` directed the popup comparison below. The policy allows eligible outgoing popup relationships; the source has no `window.open`, `window.opener`, or `postMessage` call.

The Artifacts binding must report the exact service or explicit local simulator remote and an explicit read scope. The `info()` call adds no authority callback. Existing quota, private custody, and late-reply handling remain in force.

The workspace alarm's local deletion is not provider revocation. Revocation remains owed under the existing provider workflow. The spent-invitation terminal decision applies to the native `invitation-used` and `invitation-expired` guard refusals. Other refusals and lost replies retain the original signed request. A saved completion marker permits interrupted private cleanup to resume without resending.

Counter's open 0.8.0 presentation identifier is `sha256:9a046642d592ee5877de78871f810dca639c89abb6e4a9ae7d55c10ced278753`. The semantic and definition identifiers are unchanged. No signed release packet changed.

### OAuth popup decision evidence

Planner ruling `be8d9c03d47a5abde32f96e0403293112d600222` directed a local popup comparison. Google Chrome for Testing 153.0.8010.12 opened the actual consent HTML and script from a different origin. The existing consent route retained `frame-ancestors 'none'`. The scripted context satisfied the actual consent script's issuer, client, callback, state, challenge, resource, and scope checks. Cancel returned through the actual `oauthCallback` and `location.assign` to the client origin. The callback recorded its opener and attempted a message to the exact client origin.

With no consent COOP header, the callback saw an opener and the client received the message. With `same-origin-allow-popups` on the consent HTML alone, the callback saw no opener and the client received no message. Both controls reached the callback with the expected error, state, and issuer. Thus the navigation itself completed, but the opener-dependent popup return did not survive the header. This result supports keeping the OAuth response unchanged while retaining its frame rule and context validation. A same-tab return does not depend on an opener; this fixture did not separately run a same-tab browser control.

The context and callback authority were scripted, and the result covers an `access_denied` callback rather than a successful grant. The existing native consent test exercises real selected-room and key behavior, but no ready browser fixture performs Allow without additional room authority setup. A successful callback needs such a local room and synthetic browser-key fixture, plus the actual grant path. No provider was contacted.

The Site standards assessment keeps the Page and OAuth surfaces distinct: the Page policy applies to its own routes, while OAuth retains `frame-ancestors 'none'` and its validated callback. The generic security guidance recommends assessing incoming OAuth popup dependencies before applying COOP. This measurement found such a dependency in the scripted client. It does not establish a separate Site-wide browser audit or require a Site change.

Site renders ordinary links and routes images under `img-src 'self' https: data:`. Its attachment response already carries a bare `sandbox`. If Site adds the same bare sandbox to its page response, ordinary same-tab links and routed same-origin, HTTPS, and data images are expected to remain available. CSP derives its [`self-origin` from the response URL](https://www.w3.org/TR/CSP3/#parse-response-csp). Downloads may be affected: the HTML Standard restricts downloads initiated by a [sandboxed source navigation](https://html.spec.whatwg.org/multipage/browsing-the-web.html#source-snapshot-params) and by [download links](https://html.spec.whatwg.org/multipage/links.html#downloading-resources). The Site baseline and the proposed changed behavior were not exercised in this work. No Site source changed.
