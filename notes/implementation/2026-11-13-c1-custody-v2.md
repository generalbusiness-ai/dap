## A record holds the signings of one request

`Custody` writes `v: 2` for each new record. A version 2 record keeps each
version 1 field at the top level. The top-level `meaning` and `envelope` are
those of the latest signing. `signings[]` lists every signing with its intent
digest, `meaning`, `notAfter`, `dead` and `closed`. Only an earlier signing that
is not closed holds an envelope in `signings[]`, so the latest envelope is never
written twice. Each outcome carries `signing`, the index of its signing.

`Custody.#read` is the one place that reads a version. It reads a version 1
record as version 2 with one signing that holds every outcome. A version 1
refusal of class `never`, or `expired`, marks that signing dead. A version 1
`mismatch` record has its signing closed. `outcomes` and `decided` read a
segment outcome with no `signing` as signing 0. No store parses a record past
its identity, phase and times, so no store changes for version 2, and the store
format word stays `2`.

## Custody checks three bounds before it signs

A further signing is refused, and `build` is not called, in three cases:

- The record holds `ENVELOPES_MOST` (8) envelopes: `full`, reason `signings`.
- The record holds `SIGNINGS_MOST` (64) signings: `full`, reason `signings`.
- The record and the caller's `bytes` do not fit `RECORD_BYTES` with room for
  an outcome: `full`, reason `bytes`.

`Custody` drops no envelope to make room. It drops the envelope of an earlier
signing when that signing closes, and never the latest envelope.

## `resign: true` permits a new signing

`send` takes `resign: true`. With it, `Custody` signs and sends a new signing
when the record is `refused`, or when the record is `prepared`, `sent` or
`unknown` and its latest signing is dead. Each new signing starts a new attempt.
A `refused` record is admitted against the 256 unresolved records under
`exclusive`, as a resubmission is. In every other case `send` behaves as it did
before, and another meaning throws `conflicting`.

`resign` refuses with `conflicting` a record with preparation steps, a
standalone record and a creation. A step is keyed by the digest of the intent it
prepared, so a second signing would leave the steps of the first behind. An act
with a preparation step therefore takes no second signing. Ruling `0767a3f9`
rules on that limit at C3.

## A signing is dead by the three rules of section 3

`Custody.dead(signing)` is true when one of these holds:

- The clock of `Custody` is at or past `sendableAt(notAfter)`, which is
  `notAfter` plus `EXPIRY_MARGIN_MS`.
- The scope refused the signing with a reason whose `REFUSAL_CLASSES` class is
  `never`. The signing records `dead: "never"`.
- The scope refused the signing `expired`. The signing records `dead: "expired"`.

## A refusal settles nothing

`refused` stays in `TERMINAL`, so a refused record counts in no capacity, is
archived like each terminal record, and is not sent again without `resubmit` or
`resign`. `settle` asks the scope for a `refused` record while one of its
signings is not closed. It asks with each kept envelope, newest first. A receipt
moves the record to `accepted` for that signing. An archived settlement moves it
to `archived`. A `not-found` closes a signing that is dead.

A refusal never closes a signing by itself. A held copy of the same bytes can
still reach the scope, and a live signing can be sent again. A signing closes in
three ways in C1:

- `settle` reads `not-found` for it after it died.
- `absent` states that a journal read after its death does not hold the key.
- The scope answers `mismatch` to it, or a fold names another intent.

An unresolved record always asks with its latest signing, as version 1 did. A
`not-found` does not close that signing.

`mismatch` closes the latest signing. When the record has earlier signings and
the caller passes `read`, `send` asks the scope with each earlier kept envelope
in the same call. A receipt makes the record `accepted` for that signing. A
`not-found` closes the signing. When every signing is closed the record stays
`mismatch`. A lost read leaves its signing open, and the next `settle` asks
again. Each answer is kept as it comes, so a crash between reads loses nothing.

## The replica settles a record

`folded(identity, { fact, intent })` makes no request. When `intent` is a
signing of the record, `Custody` appends a `{ folded }` outcome for that signing
and moves the record to `accepted`. Otherwise the record becomes `mismatch`,
each signing closes, and the outcome has `signing: null`. A record that is
`accepted`, `archived` or `settled` does not change. `decided` gives a
`{ folded }` form, and `send` gives `{ record, folded, retained: true }` for a
folded record.

`absent(identity, signing, head)` closes a dead signing and drops its envelope,
unless it is the latest signing. A signing that is not dead by the clock of
`Custody` does not change. `Custody` keeps no copy of `head`.

The MCP service, the hosted agent and `install-request.ts` each read a folded
record as `unreadable`, because none of them holds a replica. None of them calls
`folded`, and a fold that another client of the same store made has no answer
that they can project. `errors.test.ts` shows the MCP service case: after a
fold, `settle` and a repeat of the act give `unreadable` and send nothing.

## Each store and its change

| Store | Read by target and change signal | Terminal records it keeps live |
|---|---|---|
| `memoryStore` (`custody.ts`) | `byTarget` and `observe` | every record, for the life of the process |
| `fileStore` (`node.ts`) | none | the newest 1,024, each updated in the last 30 days |
| `sqliteStore` (`mcp/src/sqlite-custody.ts`) | none | the newest 1,024, each updated in the last 30 days |
| `durableCustody` (`examples/commons-bill`) | none, spreads `fileStore` | as `fileStore` |
| `durableRequestStore` (`examples/repo-in-ai`) | none, spreads `fileStore` | as `fileStore` |

`fileStore` and `sqliteStore` archive when they write a terminal record. Each
terminal record past the newest 1,024, and each one not updated for 30 days,
moves to the archive. `read` still finds an archived record, so `settle` still
works on it. `byTarget` lists only live records. `FILE_STORE_BOUNDS` and
`SQLITE_CUSTODY_BOUNDS` hold both numbers.

`byTarget` and `observe` are optional members of `CustodyStore`.
`ClientCustodyStore` is a store that has both, and `memoryStore` returns one.
`byTarget` takes an identity with no key and lists each live record of that
service, membership, signer and target, whatever its phase. `observe` calls its
listener after each write and returns the call that stops it. NF-5 gives both
members to the browser store and states its terminal records.

The port reads and writes `StoredCustodyRecord`, which is version 1 or
version 2. `CustodyRecord` is version 2 alone, and `Custody` returns it.
