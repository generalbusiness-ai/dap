## Routing prefix

only to a carousel over a complete `many` item source. The interpreter
evaluates it over `{viewer, item}`. The trusted viewer carries a native
`MemberRef` and current grants; the production port uses authenticated
session claims and current membership standing, never the display handle.
Missing/foreign identity, failed evaluation and nonboolean results refuse
as unavailable. Record-by-id views have no routing rule.

The native projection remains complete in server-held admission data. A
routed app display omits that raw data entirely and exposes only its card,
own queue count and exact scope/head metadata. An empty routed result keeps
the read point without any native source rows. Pre-sign admission rereads
the routing rule, so a changed route at unchanged item revision refuses.
Only routed carousels gain their constant controls on the summary page.

## Declared related reads

A routed carousel can declare one to four named `reads`, each containing
an existing projection name and `scope: "installation"`. Package binding
requires that projection's definition to be the semantic entry definition;
explicit-item sources are refused because no caller item binding belongs
to a related read. These reads keep all existing native projection limits
and authorization. They accept no arbitrary scope or item selector.

The rule input adds `scope` (the verified primary scope) and `reads` (the
named exact native projection results). Each read contributes its own
scope/head to the displayed metadata. They are separate read points, not
an atomic cross-scope snapshot. Admission rereads every declared read and
the rule before signing. Raw related rows stay inside the interpreter.
