## Bookkeeping checkpoint

`ArchiveRows` keeps one bounded metadata row in the scope's existing
SQLite `meta` table. It records the scope, resolved repository and object
format, last confirmed position and at most one outstanding mark. The
mark holds parent, cutoff, exact manifest bytes, candidate commit and
mark time. It holds no entry or retained-input body. Its caller must
admit and validate the selection before marking; the store itself grants
no export permission and does not certify the opaque manifest.

The store probes the row's native byte size before fetching its body,
then checks canonical JSON and exact fields under the same caller budget.
Target changes, replacement of an outstanding mark and a confirmation
for another commit refuse. The confirmed cutoff must advance. Each
mutation is synchronous and transactional, with no host read or journal
append. Returned snapshots have their own bytes and objects.

metadata mark survives native eviction and a later genuine turn. A

commit changes no journal head. Another witness refuses an oversized row

native bounded reader and keep its current foreign-copy and domain

without any SQL read. Every read uses the caller's original budget; there
is no current-head read, retention scan or replacement dependency.

## Scripted-host driver checkpoint

`ArchiveDriver` runs one bounded pass at a time and coalesces concurrent
requests for that pass. It reads the native admission pin before asking a
target port, uses the stored repository after resolution, and plans or
rebuilds through A1. A marked retry is persisted before host calls. The
retry delay uses the existing dispatch base and maximum, with doubling;
new turns cannot replace the marked bytes or shorten that backoff.

Only read-back can confirm a mark. The driver's send reply, including an
unknown/lost reply, cannot confirm it. An unexpected ref stops as conflict.
Missing input or a differing rebuild stops before another mint or send.
Credentials remain local to a pass, with bounded cleanup or expiry, and
never enter the archive row or history. The original deadline fences late
continuations and their ability to send.

The payload row now records attempts, next retry and a stopped reason.
A separate alarm index is at most 256 bytes; it stores no manifest or
second outstanding commit. New turns only touch that index. Confirmation
and its follow-up wake are written in one transaction, so entries that
arrived during a send remain scheduled. A persisted stop is not silently
restarted by a new entry.

Thirteen focused cases across row, build and driver files pass on real
Durable Object SQLite (`77206` / `2e9b43`, exit 0); the test typecheck
passes (`6a68f0`). Driver witnesses use explicit fixture policy/authority,
credentials and host stand-ins. They cover lost reply/read-back without
a second commit, actual eviction after Mark before any object reached
the scripted host, a later native rule-input turn, the original first
commit then the new prefix on top, and offline native replay from that
object store in both Git formats without anchors. This object-store replay
is not a new real-Git clone witness. The A2 clone evidence remains separate.

Another witness holds a scripted send while sixteen real native turns
complete, with duplicate driver requests joining one pass. The deadline
witness advances an injected elapsed clock and proves a late continuation
cannot send or confirm; no sleep or timeout widening is used. Actual
`ScopeObject.alarm` integration is still due. The first driver typecheck
found nullable-clock/retry narrowing errors; explicit guards corrected
them before the passing run.

This checkpoint defines bounded provider and target ports but activates
none. Scripted-host prefix checks are stand-ins, not evidence of the
actual provider adapter's security boundary. That adapter, concrete
target resolution and alarm integration remain required A3 work.

## Actual adapter send boundary

GitHub and Artifacts expose an explicit `fixtureArchive` constructor over
fixture token/read ports. Neither calls a real archive mint or reuses a
ledger operation, mint handle or custody row. The shared adapter binds an
owned credential object, by private WeakMap identity, to the exact four
repository fields, full native scope reference and `refs/artroom/journal/`
ref. A copied credential object has no authority through this adapter.
Revocation removes the binding before awaiting its fixture token port.

The send snapshots the command and supplied object bytes before awaits.
It checks the binding initially and again through the actual smart-HTTP
`beforeSend` boundary after compression and discovery. Expiry, revocation
or a spent pass fence prevents the POST. `sendOnce` now accepts its actual
Git send fields without inventing an OperationId or DestinationBinding.
Existing destination writes retain their original arguments and behavior.
This is an adapter guard, not a provider-issued ref permission or a new
repository identity fence against an external rename during a send.

Parent reads cap transport bytes, decoded pack object count, closure count
and copied aggregate bodies before collection. These are caller allowances,
not a measured heap bound or a claim that arbitrary real histories fit.
Both concrete smart-HTTP providers currently support SHA-1. The scripted
archive-driver host also exercises the format-neutral SHA-256 layout.

## Native alarm and target resolution

`ScopeObject.alarm` runs the optional fixture driver after native alarm,
dispatch and effect work. Sealed turns only signal a small wake index and
arbitrate the existing alarm; they await no archive host. `Wakes` considers
the archive index alongside the existing owners. Archive scheduling failure
cannot refuse an already sealed native entry. No default writer is created.

The driver persists a small retry wake before target/parent I/O can await,
including before a payload row exists. A reset before Mark therefore keeps
its retry. New entries do not shorten it. After confirmation, the same
native alarm schedules any prefix that arrived during the send.

The target resolver walks at most eight checked native births through the
creator chain. It uses existing bounded birth and authenticated item-query
RPCs, passing only the original remaining time to subordinate birth reads.
It requires one complete directory repository row, its destination's checked
birth and one complete destination branch row with the same directory and
repository. Missing, ambiguous or inconsistent records return unavailable.
No summary or legacy-source fallback, new read bypass or production reader
configuration was added. Fixture reader authority is supplied explicitly.
