## Bookkeeping checkpoint

`ArchiveRows` keeps one bounded metadata row in the scope's existing
SQLite `meta` table. It records the scope, resolved repository and object
format, last confirmed position and at most one outstanding mark. The
mark holds parent, cutoff, exact manifest bytes, candidate commit and
mark time. It holds no entry or retained-input body. Its caller must
admit and validate the selection before marking; the store itself grants
no export permission and does not certify the opaque manifest.

The store probes the row's native byte size before fetching its body,
then checks canonical JSON and exact fields under the same caller budget.
Target changes, replacement of an outstanding mark and a confirmation
for another commit refuse. The confirmed cutoff must advance. Each
mutation is synchronous and transactional, with no host read or journal
append. Returned snapshots have their own bytes and objects.

Two focused cases pass against real Durable Object SQLite. A test-authored
metadata mark survives native eviction and a later genuine turn. A
different mark or confirmation leaves it intact; confirming its own
commit changes no journal head. Another witness refuses an oversized row
before any row-body fetch and refuses duplicate-key corruption and a
spent call allowance. These marks are explicit stand-ins: no A1 commit,
native archive inventory, host, token, send, read-back or complete A3
rebuild is claimed. Focused run `65102` ended `c90cd6`, exit 0; test
typecheck `efa3d8` and whitespace checks pass.

## Immutable input-port checkpoint

`archiveInput` copies a selection's position and retained-key descriptors
and reads only those names. Each entry read probes the exact position's
hash and byte size before fetching its body. Retained reads reuse the
native bounded reader and keep its current foreign-copy and domain
refusals. A missing key, position or exact byte allowance returns no input
without any SQL read. Every read uses the caller's original budget; there
is no current-head read, retention scan or replacement dependency.

Two focused real-SQLite cases pass after a later native turn and eviction.
They show exact selected bytes, no SQL for unlisted requests, no body
substitution after named-row loss or alteration, and no SQL after the call
allowance is spent. Descriptors are explicit test-authored selections;
these port tests grant no export admission and are not the complete
reset/rebuild writer witness. Run `38657` ended `5a40da`, exit 0; test
typecheck `ba69ef` passes. The first production typecheck caught a redundant
comparison against text, which the native retained-key type already
excludes; that comparison was removed.
