`indexedScopes` is the production namespace wrapper. Before its creation
`deliver` branch calls the raw child's `idFromName` or `get`, it asks
`admitChildCreation`. This also covers instrumented `observed("deliver")`
calls. The wrapper requires the copied seed to name the exact selected
target. A successful result owns its envelope and has a final live-deadline
predicate; it is not a proof invented from a raw ID. Ordinary receiver

For each edge, the attempt reads the creator's exact birth and exact
sealed send. It checks full reference and incarnation, canonical entry
bytes and fact hash, the child's recorded source-use content digest,
ordinal uniqueness, exact seed and message, and `seed.creator` equality.
Every ancestor genesis must be applied. The next edge comes only from
that genesis's own recorded creator/source/message. A refused genesis is
negative evidence. The walk stops only at the configured, applied native
register install. Native edges are register→Directory,
Directory→Membership/Rules/Destination, and Membership→Inbox with the
same selected cohort's exact pins. Other native kinds remain unsupported.

## Root declaration and descendants

A declaration is not admitted because a Directory can return some bytes.
The authenticated Directory's exact native create send first binds the
root digest. The 17 cohort's reviewed native rules require its retained
application catalogue; the 5 cohort's original rules require its activated
root and complete named closure. The serving attempt then reads that
root and **all** static child definitions from that same Directory,
checks exact canonical bytes/digests and validates every declaration.
Every later declared creator and child pin in this lineage must be in
that rooted closure. The ordinary receiver separately judges its full
genesis. A label, name or separately supplied declaration proves no root
or descendant membership.

The narrow private `creationDeclaration` RPC returns only bounded immutable
declaration bytes for an exact current full Directory reference under one
of those two pins. It performs size metadata checks before loading a
definition or a retained JSON text. Stored JSON text has a separate
six-times-plus-two representation bound before decoding. It uses the
existing native catalogue locator, not a new scan of all items. It calls
no `#first`, turn, dispatcher, provider, network or archive port. This is
custody, not an independent assertion of installed closure or authority.

## One attempt and unavailable history

One attempt permits at most 16 bodies, 1 MiB combined UTF-8 bytes,
64 source/index attempts, 512 visits and one monotonic 10-second deadline.
The initial copied envelope counts, as does each distinct birth, source
entry and declaration. The existing platform JSON codec admits escaped
UTF-8 length, descriptors, cycles, a 100,000-node ceiling and depth 64
before serialization or expanded UTF-8 allocation. Its ordinary own-key
enumeration assumes plain RPC data; this is not a hostile-Proxy or OS
allocation guarantee. The 512-visit bound concerns the lineage/closure
walk, not every property examined by that finite JSON codec.
Index/RPC attempts count before dispatch. Every
external await rechecks the remaining deadline before another lookup or
the final child activation. The RPC receives only the remaining body/time
allowance; no hop or declaration resets it. A late result cannot resume
the walk or touch a child. Cycle detection uses full references. These
are serving ceilings at or below GenesisProof's, without its causal-root
algorithm or cache.

The complete closure may exceed the remaining body count or byte budget
even when a native application package is otherwise valid. Admission then
returns unavailable before child lookup; it never truncates the closure
or silently widens a ceiling. Missing/archived proof, missing declaration
custody and a spent deadline return the existing
`retry/dependency-unavailable` answer and preserve the sender's task,
without a child lookup. Malformed, wrong-root or cryptographically
inconsistent creation is refused as a routing failure. There is no
`source()`, caller-anchor, network or archive fallback.
Ruling `fc7099fc` requires bounded retained-edge support before floors
are enabled on scopes that have created children. That support is not in
this first slice. Existing floors remain unchanged and off in production;
F3's proposed Room A has no created scopes.

The local/test opening remains explicit: no `DEPLOYMENT`, or exactly
`ALLOW_OPEN_CREATION="true"`, uses the prior local child path. It is not
a hosted recommendation. Parentless directory creation remains refused
in deployed closed mode under the earlier R1 policy.
