## What changed

The package subpath derives projections and manifest fields from the
definition value. Authors still choose displayed slots, layout, roles,
assets and browser entry. A roles-first declaration supplies the action
union that acts may use. The manifest checks role coverage and view
field names at compile time and at runtime. Lending and Counter declare
their roles before constructing their real grant maps.

The story subpath uses the maintained judges, rule preparation and fold.
Each queued step checks the author's expected answer and its complete
entry, effect, send and timed-firing assertion before it emits scenario
v1 data. Projection steps read the resulting fold. Explicit TEST seeds
and scripted grants supply local authority, with membership and
destination references as named stand-ins. No service or outside driver
runs during story generation.

The Lending and Counter package sources derive their existing manifest
data. The Lending story source records all outcomes beside its steps.
Their tests compare formatted output with the original independent
files. Source keeps authored metadata order; no generator reads an
output file as a formatting template.

`extend` records an additive child of a compiled parent in a WeakMap.
It preserves the parent's inherited forms and reports the parent digest
and sorted added form names through `compile.provenance`. The pinned
declaration carries none of that metadata.

## Decisions and why

The existing act helpers widened a grant literal to `GrantRef<string>`.
Their final generic parameter now retains that literal without changing
runtime data or the previous type-parameter order. This lets the actual
manifest builder reject an action that no declared role holds.

Story assertions belong to their individual steps. They compare the full
ordered effect and send lists from actual judge drafts after sealing and
folding. An act or founding step also owns every timed firing that
becomes due immediately after its write. Assertions never derive an
expected effect from the definition being
tested. The emitted file keeps scenario v1; the CLI schema stays as it
was. Package derivation and parameters remain reserved for P5.

The first source review found six gaps. The timed witness now founds an
untimed root and opens a separate timer before advancing the clock. This
keeps the validator's `genesis-timed` refusal intact. The release plan,
existing export witness and SDK table now include the two new subpaths.
Story generation rejects empty slot-only assertions, invalid saved names
and scenarios that only advance time. Item projections reject detached
text, as the maintained package binder requires.

The second source review found two extra-field paths through typed
variables. Story generation now rejects unsupported own fields in
founding data and item assertions before emitting their closed v1
objects. Supported properties keep their authored order, including an
empty optional slot map beside a real state assertion.
