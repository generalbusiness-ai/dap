# Reuse private Artifacts credentials for Site reads

R4 item 1 adds private, expiring Site read-token custody at the existing fixed `ScopeIndex`. Repeated Artifacts reads reuse an unexpired credential instead of minting and revoking one per request. Ordinary gate `85802` passed on the current production checkpoint, with its closed evidence independently audited and accepted. Earlier gate `58930` and follow-ups `13339`, `38510` and `16504` remain failed at their original checkpoints. Authentic exact-head review remains pending.

The binding-only `acquireSiteRead` key includes current canonical configuration, full repository identity and validated published ref. Branch aliases use the selected native ref; immutable reads use their written receipt ref. Native publication/receipt and Git checks still run, with fresh configuration and provider-reported remote checks on credential acquisition and fresh native eligibility before content or 304. Reuse grants no publication authority. GitHub keeps its existing path.

Custody admits 256 keys and 32 durable mint reservations, with eight followers per flight and 64 overall; the leader is separate. Capacity returns finite 503 without evicting live keys. A reservation precedes provider awaits. Ready replies require read scope, bounded plaintext and valid future provider-reported expiry. Reads never extend expiry. Ready custody survives eviction; acquisition and fixed-owner alarms reclaim expired rows while preserving earlier alarms. Failed scheduling after installation clears plaintext but keeps the known expiry/key.

Before mint entry, failure releases only the request's reservation. After entry, an ambiguous or invalid answer holds the reservation for the requested 120 seconds plus 60 seconds, as planner ruling `3fdb03b9` permits. Generation/state/expiry CAS prevents a stale reply from installing over a successor. No inline mint retry follows a Git 401 or network failure. Close drops the request-local source and secrets without revoking shared custody. This is local ownership, not physical provider exactly-once behavior: an inaccessible late provider token may outlive the hold.
