The package test setups intercept only the actual `judge.ts` exports
`judgeAct` and `judgeActForReplay`. Each wrapper passes the original
arguments to the original function once and returns the original answer.
It encodes the answer before the owner can seal, fold or mutate its
contents. It does not copy or replace a StateView, CheckedSequence, proof
reader, callback, clock, definition, signed intent or context.

The two lists remain separate. A case identity includes the owner, the
test's full suite/name path and its structural position within the file.
Judgments made during suite collection use the owning suite's path, an
explicit collection marker and that suite occurrence's local position.
Each list and case counts its calls from zero. The harness moves no
fixture setup and drops no repeated call, including repeated replay text
gap judgments.

The tagged answer encoder distinguishes absent properties from present
`undefined`, preserves Map and Set iteration order, and distinguishes
array holes and exceptional numbers. It sorts plain object keys for its
canonical bytes. It rejects unsupported values and accessors rather than
silently omitting them. Those tags describe evidence only; the harness
never decodes them into objects for a judge.

For each case, the fixture stores the list, owner, label, call count and
SHA-256 over its call-ordered answer hashes. The aggregate hashes the
lowercase hexadecimal hash of each answer followed by a newline. A
missing case, extra case, changed count or changed aggregate fails. The
comparator does not realign calls or treat one list as the other.
