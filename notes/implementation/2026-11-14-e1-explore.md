## Preserve every answer at its original call

Ruling `8c43e2a021fbfba142e8bc274e1fd47ff1410800` replaces items 5
and 6 of ruling `3316caa5e05637e9f2956b07d4d529eb8962d69c`. The
oracle records answers without input hashes or reader wrappers. The shared
Ledger lives in `packages/derive/test/fixtures.ts`, as the ruling confirms.
The earlier source audit is `db7c98513a5c14bc73dd0778bea37306ee70eb4c`.
Its size lower bound concerned a superseded per-call hex-row encoding,
not the current aggregate fixture or an actual produced size.

The package test setups intercept only the actual `judge.ts` exports
`judgeAct` and `judgeActForReplay`. Each wrapper passes the original
arguments to the original function once and returns the original answer.
It encodes the answer before the owner can seal, fold or mutate its
contents. It does not copy or replace a StateView, CheckedSequence, proof
reader, callback, clock, definition, signed intent or context.

The two lists remain separate. A case identity includes the owner, the
test's full suite/name path and its structural position within the file.
Judgments made during suite collection use the owning suite's path, an
explicit collection marker and that suite occurrence's local position.
Each list and case counts its calls from zero. The harness moves no
fixture setup and drops no repeated call, including repeated replay text
gap judgments.

The tagged answer encoder distinguishes absent properties from present
`undefined`, preserves Map and Set iteration order, and distinguishes
array holes and exceptional numbers. It sorts plain object keys for its
canonical bytes. It rejects unsupported values and accessors rather than
silently omitting them. Those tags describe evidence only; the harness
never decodes them into objects for a judge.

For each case, the fixture stores the list, owner, label, call count and
SHA-256 over its call-ordered answer hashes. The aggregate hashes the
lowercase hexadecimal hash of each answer followed by a newline. A
missing case, extra case, changed count or changed aggregate fails. The
comparator does not realign calls or treat one list as the other.

## Capture once before the split

After root grants the slot, give the isolated worktree an owned dependency
view that matches its unchanged lockfile. Run the capture from a clean,
committed harness checkpoint:

```sh
node scripts/e1-judge-oracle.mjs capture <new-directory-under-~/play/artroom-evidence>
```

The command checks that only the named harness and note paths differ
from the baseline. It applies the maintained compatibility backport and
runs the existing owners once through the normal root Vitest configuration.
It refuses an existing destination. Each owner writes a separate raw
answer file, including an empty file if that owner reaches no act judge.
The command requires exactly the named owners in the test results and all
owner answer files after the tests succeed. It then
writes `answers.jsonl` and the proposed aggregate `judge-answers.json`
outside the checkout. A failed owner stops fixture adoption.

Report the aggregate's actual byte size before copying it to
`packages/derive/test/fixtures/judge-answers.json`. Ruling `8c43e2a0`
does not impose the earlier proposed object limit on this fixture. The
implementation note still has the repository's 40,960-byte ceiling.
The capture's actual path and SHA-256 will go in this note after the run.
No raw answer fixture or aggregate exists in this source checkpoint.

The package setups compare with the committed aggregate by default, so
the normal owner run and gate exercise the comparison without a second
copy of each owner. Oracle owners must run as whole files; a name filter
that removes calls fails the comparison. The explicit comparison command selects the same
owners:

```sh
node scripts/e1-judge-oracle.mjs compare
```

The committed rows alone decide whether comparison passes. On a
difference, diagnostics print the case, both call counts and every
current answer of that case. Set `ARTROOM_E1_ORACLE_RAW` to the retained
`answers.jsonl` to add the first differing call and its baseline answer.
The helper checks those raw bytes against the committed case rows before
using them. Missing or invalid optional raw capture does not change the
comparison result. The diagnostic instead prints commands to create a
baseline worktree at the recorded capture-only harness checkpoint. The
capture command checks its unchanged production and owner bytes against
`270dc8c7` before it can produce answers again.
