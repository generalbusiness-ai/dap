# Keep room identity through a roster refresh

## What changed

A row press can now keep the last complete room identity while another draw reads the roster. The Page shares one pending roster read per room, then publishes the completed standing in one step. An unsuccessful read still clears standing and refuses the caller. Both action discovery and the change's reviewer choices use that read.

The browser harness now retains the selected URL, visible draw, DOM, screenshot, console diagnostics and request metadata when a row fails to open. Its bounded probe alternates the two J5 rows within each of 20 fresh tabs, five presses per tab, and stops at the first failed opening or 100 openings. The normal scene also starts capture after the device joins. Captures withhold invitation fields and redact credentials. Request records contain no headers or bodies. The shipping harness contains none of the temporary diagnostic observers.

This head answers row-press request `3b7c6b0b`, promise `510f23bf`. Request `ff7f7671` owns the deployed rerun and its record. J5 acceptance stays open.

## Decisions and why

The first ordinary local run failed on press 15 after 14 openings. It selected the export issue but drew **Observation unknown** and **The view could not be read**, without a comment slot. A replay against that same retained Worker store failed on opening 80 after 79 openings. That replay captured the exception: **Refused because this key has no verified membership in this room.**

The code explained that refusal. `refreshStanding` set `room.me` to null before awaiting the membership read. `RoomOpening` caches the same room object, so another draw could receive it during that gap and fail `verifiedRoom`. The change's reviewer-roster read had the same gap. The controlled native test holds the actual HTTP roster response pending and checks the identity another caller sees. The original code fails its named assertion. The fix preserves the completed identity during the read, shares the pending promise, and clears standing on failure. Callers still await the fresh authenticated roster before offering acts. A real permission change removes the act.

Three diagnostic attempts each opened all 100 rows but still exited 1 because their final console check caught stream HTTP 503 responses. They used, respectively, a CDP breakpoint, browser script routing, and an Error instance-check observer. Each can affect timing. None proves absence of the race. The original-room replay retained the last observer and captured the exception. No observer followed that replay: the native test and code read established the cache gap.

The fixed verification used the original Worker store and the replay's retained Ana device key. The script added no observer, routing, injected fault or cache override. It opened all 100 rows with no native act and unchanged issue heads and items. All 21 browser script responses matched the checkout and Worker bytes, digest `cc8189fb8b8b072ab3b6c73e77d276b562bb62b69b3ac19dda6c5eddb2504142`. Its predeclared console rule counted 30 `/stream` HTTP 503 diagnostics separately and failed on any other console error. It found zero other errors. This is bounded local script evidence.
