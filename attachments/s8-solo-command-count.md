### Count the same bounded task

several Native acts. Start with a configured publishing register, the

For this comparison, the first change writes an ordinary content path such

The protected Rules extent keeps its minimum. All names, definitions and

### Exposing the certified protocol adds commands

There is **no complete maintained new-family command path or exact new
command count yet**. Current `line.ts` exposes generic `act`, but no policy
preparation or certified-publish command. The certified Native contract
needs a complete policy proposal, current repository tree proof, a
`certify-rules-tree` request, its later certificate result, and a publish
bound to those exact facts and values. `dap act` reports its accepted
request entry; it does not wait for that certificate operation and publish
Rules afterward.

If the family exposes those steps separately through today's generic
commands, the comparison has a **lower bound of six DAP commands**, rather
than four: the four existing phases, plus a certification request and at
least one observation to obtain its result before the solo publish. This
is a lower bound, not an invented runnable six-command recipe. Policy and
tree preparation, finding complete birth/certificate references, and
retrieving placed proof bytes can add further user work or reads. No
existing CLI source proves the exact total. The new command count would
therefore be larger on that manual path. The planner must rule before the
family source opens.

The proof's tree must match the actual published branch. An unmatched
pattern needs the existing explicit future permission for that occurrence;
bootstrap must not silently invent it. The new Destination must keep
`rules-not-configured` until the first certified publish. A default value
or a pure decoder result is not that publish or its certificate.
