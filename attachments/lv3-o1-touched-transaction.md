# Decision draft: live O1 touched-row transaction

## Proposed direction

Give `MemoryState` an internal, synchronous, non-nestable transaction available only to the live caller. Instrument the existing state mutators with a journal when that transaction is active; with no transaction, they retain their current behavior and recorded folds see no semantic change. The smallest shared derive surface is one internal method such as `state.liveTransaction(work, decide)`, with `work` running the existing `applyLive` against that same state, and `decide` receiving a read-only changed-row summary and proposed post-fold item states. It returns committed, refused, or throws after rollback. It must not call user code, await, send notices, or arm timers while provisional writes exist. A narrow internal API is needed because the maps, array positions and set edges are private. Its detailed type and a map-order decision need planner approval before implementation.

Each primitive map mutation records `(collection, key, existed, previous value)` before changing it. For each set add/delete, record whether the edge existed; for array splice, record the exact bucket identity, insertion position and removed elements, and undo in reverse order. Do not copy a whole state or whole large index bucket. For map values whose existing nested content may be mutated, journal the in-place operation itself or replace that touched bucket with a copy-on-write bucket before mutating; `#index` and `#keyed` arrays and `#fixedDependencies` sets require this explicitly. All undo operations bypass the journal. Journal the prior scalar for `#scope` and `#fixedReady`. Preserve error cleanup when canonicalization, a write, accounting or the fold throws, including partial execution of `putFixed`.

The transaction keeps one initial record for every changed logical key and one final record, even when the fold updates it repeatedly; its journal may keep every inverse operation to restore exact intermediate ordering. Derive a delta from old and new encoded records only for dynamic categories. For touched item ids, use their initial and final item to calculate `delta(E_type + deadlines[type][state]*T_type + attributedCharge)`. Item envelopes cover row/index changes; separately charge global bucket/count keys where required. The dynamic delta includes fixed hashes, accepted keys, detached history, authority observations and genesis/confirmation rows, under an explicit canonical framing. Update the held total only on commit. Check all arithmetic including reserved potential for overflow. Prove categorized fixed rows and dependencies fit the envelopes before excluding them from dynamic charging.

## Mutation inventory

The fold of a normal live act or timer can perform the following, and a live generation first folds its recorded genesis and possible confirmation. A writer callback can do several of these even for one effect:

- `putItem`: set item map; splice old and new `#index` state buckets, possibly create a bucket; `addCount` sets old/new count keys and retains zero rows. Attribution is part of the item and can grow on an act.
- `putFixedHash`: set a per-tick hash. `rekeyFixed` can visit *other items* whose raw local references name this tick. `putFixed` sets `#fixedRows`, `#fixedRaw`, `#fixedRowDependencies`; sets or deletes two `#fixedCounts` keys before and after replacement; mutates, creates and deletes sets in `#fixedDependencies`; and inserts the new count keys. Multiple rows and dependencies can share keys. Log at each primitive mutation, not once per top-level writer call.
- `putAccepted`: set one `(actor,key)` row only for an applied act. `putObserved`: set a highest observed head and append a previously unseen genesis to the per-scope array. A timed input has no authority proof. `putTexts` replaces or deletes detached-history entries; values can append digests, and a redact can remove the row if that effect is admitted.
- `setScope` replaces scope/head/time/status; `finishFixed` replaces fixed-ready. When opening a keyed item `putIndexed` may create a `#keyed` bucket, splice its id and set `#rows`; ordinary live declarations disallow platform indexes, but genesis coverage must not rely on that without proof.
- Genesis or creator confirmation may also invoke `putDecided`, `putRequest` and `#pendingRequests` add/delete, `putCreation`, `putRelation` and `#copies`, plus `putObserved`/`#geneses`. Whole-capacity forms may invoke `putItemDuties` (set/delete), `settleHolder` (set add), `putHolder` (set/delete), or `putAccount`. Generic fold paths additionally expose `putSourceOrder`, `putOperation`, `putPrepared`, and `putRecord`. Live form restrictions make several unreachable for live acts/timers, but initialization must explicitly enumerate and prove its supported genesis/confirmation paths. Instrument all these mutators or enforce an exhaustive scoped writer boundary; silently ignoring a supposedly unreachable write is unsound.
- `putFloor` changes the floor and deletes many hashes. A live input is act/timed and may not invoke it; verify creation contains no floor. Treat it as unsupported in a live transaction until that proof exists, without changing ordinary recorded behavior. No history/hash pruning is proposed.

`#floor`, `#scope`, `#fixedReady`, `#fixedRows`, `#fixedRaw`, `#fixedCounts`, `#fixedDependencies`, `#fixedRowDependencies`, `#fixedHashes`, `#items`, `#index`, `#counts`, `#relations`, `#accepted`, `#requests`, `#pendingRequests`, `#decided`, `#sourceOrder`, `#creations`, `#operations`, `#texts`, `#prepared`, `#records`, `#observed`, `#holders`, `#itemDuties`, `#settledHolders`, `#accounts`, `#geneses`, `#copies`, `#keyed`, `#rows` are the complete current private storage inventory. Optional `tally` is instrumentation and must not be aliased or incorrectly counted. A checked registry or source-inventory test must catch new storage or direct mutations that bypass journaling.

## Admission, retry and timer

Let `U = dynamicCharge + globalCharge + sum_i(E_type(i) + D(type(i), state(i))*T_type(i))`; `D` is `ValidDefinition.deadlines` and `T` pays one timed hash plus the maximum detached-history append and its framing. Initialization charges the actual creation folds plus every initial item reserve before publishing the generation; how to handle an initially unaffordable valid creation needs a ruling.

For a fresh act: enter the synchronous transaction, fold, calculate candidate U from changed keys and items, then commit only when `U <= B`. Otherwise reverse every inverse and return `scope-full` at the unchanged head. No accepted key, observed head, item, index, hash, history or notification from the candidate remains. `accepted()` and `judgeAct` run before the new-write transaction as today, so an accepted exact retry returns its original recorded tick even at capacity. A mismatch still follows existing judgment. Timed work drained before a subsequent refused act stays committed and may advance that act's refusal tick: the refusal preserves the state immediately before that act's own provisional fold.

A timed transition from item state q to q' spends `D(type,q)*T - D(type,q')*T`. Validation's acyclic graph and its edge definition must establish `D(type,q') <= D(type,q)-1`. Each rule changes its own item only, opens nothing and does not take signer attribution, so one released T covers the fixed-hash addition and every possible detached-history addition. Item/index changes, including rekeys of other items, fit existing E envelopes; global metadata has a prepaid maximum. On a valid invariant the timed candidate U never increases beyond its prior reserve. Commit it even when no fresh act fits. Any violation rolls back and takes the existing broken-generation path, not a silent timer refusal. Timers and acts both use the same journal and accounting calculation.

`#section` remains synchronous; its finally block sees only the committed head or restored old head. It arms a timer and sends a watch notice only after the transaction has committed; a refused act sends none for its provisional writes. If the same section previously committed timed transitions, those transitions retain their normal notice. An exception after a partial fold must roll back before reset or other callbacks.

## Order, cost and unresolved decisions

A plain inverse `Map.delete` then `Map.set` restores the contents but changes JS iteration order. That may affect paths traversing `fixedDependencies`, `all`, or other collections; it is not enough to assert equal keys. Before approval either prove every live-visible read and future fold is insensitive to affected Map/Set insertion order and test with the scratch full-clone oracle, or use an order-preserving touched-key overlay. The overlay makes writes provisional and applies them to the base only on commit, but each StateView read must merge its overlay in original mutation order, including fixedAffected, page/lookup and any aggregate reads. It does not copy untouched buckets; implementations that reconstruct an entire map to restore order violate the production direction. Array splice and Set-order restoration also need explicit treatment. This is the principal API choice for planner review.

Cost is O(changed keys + changed bytes + affected index work), in addition to existing fold operations and any array shifts. A hash can rekey many rows across many items, so the number of affected rows is not bounded by the new entry's effect count; reserve and journal all of them. Avoid copying a large history or membership bucket merely to undo one append; existing `putTexts` itself constructs an appended array, and metering a full replacement by canonicalizing it can make one act O(history size). A delta meter needs proven append/remove accounting or accept that existing changed-row cost; hash rekey and sorted-index splice also retain their inherent costs. Memory is O(journaled changes + retained changed values), plus the fold's existing temporaries; no claim bounds V8 peak memory from logical canonical bytes alone.

Before implementation, prove complete creation/confirmation reachability and source value size bounds; prove E and T include all nested encodings and both dependency directions; specify logical entry framing and checked B; choose and prove the insertion-order solution; and test real-scope full refusal, retry at capacity, due timer and cross-item future-hash rekey against the scratch clone oracle. No tracked files changed and no tests ran.
