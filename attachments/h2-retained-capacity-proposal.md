# H2 retained capacity terms

Status: proposal for the unnamed retained-byte terms under ruling `af46b9ecbaa2ad7309a36951f3d31a5df8f614ff`. The H2 source checkpoint `f501b7f4e7524af978145fc0c82d796537e836e8` does not implement whole-attempt admission or Native custody. This proposal states conservative terms to review, not measured storage usage or a new wire format.

## Existing owners and limits

An `Amount` has entries, items, records, bytes and requests. `capacityFull` compares all five against the scope bounds. `reserved` accounts for existing pending holders, item duties, requests and other defined obligations. The SQLite owner counts canonical UTF-8 journal bytes and retained bytes, with retained rows keyed by their domain and digest. A repeated identical retained row does not add another row's bytes. A prospective quote must not assume such deduplication unless the same checked storage snapshot proves it.

`capacityOf` already creates a selected sequenced-act amount from `entryFor(form) + entry + starts(form.sets) + requestsOf(form) + marksOfForm(form)`. The first entry is the prepare ceiling and the second bounds either commit or abandon. `entryFor` includes the selected form's existing field, rule and opening bounds. `starts`, requests and marks use the existing validated pending-work owners. `sequencedActQuote` adds conservative group-read terms. These are prospective bounds, not exact serialized entries and not a completed H2 `owed` or allocation calculation.

Let `E` be `bounds.entryBytes`, `r` the number of declared group reads, `F(x)` the UTF-8 byte length of a checked canonical foreign entry, and `P(i)` the canonical UTF-8 page bytes for read `i`. The actual prepare and commit entry bytes are each counted once by the journal owner and must each fit `E`. The duplicated top-level and wrapped prepare position/reads both belong to the canonical prepare bytes. They are not a separate retained row. H4 must settle the duplicate-wire question before live sequenced entries exist.

## Terms for planner approval

1. **Order and cut facts.** Charge retained canonical bytes for the checked order-head entry and each distinct checked cut or leave entry named by the prepare. Actual charge is the sum of `F(x)` for each new retained identity. Before those exact facts are known, use `E` per possible fact and assume no deduplication. The note explicitly names the order head, each cut and each leave, but does not state this byte formula or a maximum leave-fact multiplicity. The current `2 * (1 + r) * E` stand-in requires a proof that it bounds every named leave fact under the actual finality representation. Do not promote it as a complete bound without that proof.
2. **Grouped pages.** Charge each distinct retained canonical page once by its page-domain digest. After checking the actual page, charge `P(i)` as UTF-8 bytes. Before a page exists, bound its canonical row array by `sequencedGroupRowsBound` for the authenticated member's selected item type and the 64-row page limit, including keys, escaping, commas and brackets. This is the existing array calculation, not proof that the eventual page codec uses exactly that frame. Approve the domain, framing and any metadata bytes before claiming the bound covers the stored object.
3. **Prepare's original input and provenance.** Count the canonical prepare entry against `E`. Separately count any new retained detached text, checked source entry, rules input or other input bytes under their existing owners and domains. Use the selected form's `fieldRetainedBytes`, `ruleInputs` and clause-retained terms where they already cover the same row. Add a new term only for a distinct row not covered there. A wrapped delivery must include its genuine retained source proof, but its additional retained identity and exact ceiling need a source-by-source proof. Do not add `E` for the same source twice or omit a separately retained domain.
4. **Terminal proof and terminal entry.** Reserve one further journal entry at `E`, because commit and abandon are mutually exclusive. If the chosen terminal additionally retains the order resolution or expiry entry, charge its new canonical retained bytes up to `E` per distinct required fact. The design names these facts but does not name their retained-byte accounting or whether another existing proof row already owns them. H4 must establish and atomically transfer the exact terminal reservation. It must not ask a settling commit or abandon to fit again.
5. **Allocation and outcome.** In the Order scope, charge the canonical allocation entry and its newly opened allocation item in their existing dimensions. Reserve one mutually exclusive resolution, hole or expiry entry at `E`, plus any new item, record, request or retained input required by the selected terminal under the Order definition's existing duty closure. Do not sum all three terminal entries when only one can occur. The exact retained bytes for a resolution's prepare fact and the allocation input's proof, and whether the timed outcome starts any extra work, need derivation from the admitted Order declaration and real source proof. H3's current reserve witness is relevant evidence, not a substitute for H2's general quote.

The pre-allocation check compares `used + already owed + prospective quote` on every axis. It must use checked arithmetic and fail closed when a producer, member binding, page bound, closure or sum is unavailable. Once a concrete prepare is derived, re-evaluate the actual canonical draft and the duties its selected effects and sends open. Count prior obligations once. Reserve the terminal plus actual newly opened work before writing prepare. After commit, move those obligations to the resulting pending owners. After abandon, consume its terminal and release the remainder. No caller-supplied amount decides this judgment.

## Ownership and witnesses

Derive owns the pure quote, exact-draft calculation, all-axis `fits`, and `owed` terms from a validated selected branch and its effects. Its tests can use real derived entries and an in-memory StateView. They must cover applied act, applied/refused/superseded delivery, allocation resolution/hole/expiry, retained identity reuse and nonreuse, canonical escaped page bounds, each five-axis equality and one-over refusal, arithmetic overflow, and every fail-closed missing producer. They must demonstrate that existing pending duties are not double charged and that prepare reserves one terminal plus its actual pending work.

H4 owns authenticated full Order/member references, retained fact and page bytes, the one-pending row, transactional durable reservation, restart/eviction, transfer and release, and the Native delivery surface. Native witnesses must establish the exact charges and no capacity-caused wait after a prepare. A pure H2 test cannot claim these storage or authority properties. Kernel review under `docs/kernel.md` section 7 and an exact full gate remain required.
