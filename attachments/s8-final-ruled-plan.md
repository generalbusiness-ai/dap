### Require global and touched-extent checks

The new Destination judges every globally required check together with
every required check of every touched extent. Successful extent checks
cannot hide a missing global check. The single-controller exception waives
no check. Successful reservation standing retains the entire union and
full job, deciding-result, checker membership/key, configuration and
captured-policy provenance. List eligibility retains those obligations for
the final gate; it does not claim earlier job success.

Missing or failed required jobs refuse `rules-not-met`; malformed or
contradictory evidence refuses `evidence-invalid`. Reuse the mandatory
`requiredChecksV14` judgment boundary while retaining Destination19's fixed
one-hour token and all other stable-family protections. Adding names to an
extent lookup without requiring every selected descriptor is insufficient.
The real Native witness must include a global check named by no touched
extent, missing/failed/forged/wrong-configuration evidence, a valid result,
duplicate names and an optional check on an untouched extent. Replay must
reproduce the final reservation and its provenance. This is the target
closure of November2.4/October3.4, not a current acceptance claim.

### Compose the certified policy, including explicit solo choices

Ruling `11f4d825` selects the certified policy for the family's default.
The default starts with a positive approval count and explicit
`ownerMayReview`. A global zero count requires `allowZeroApprovals: true`;
each zero-approval extent needs its own explicit opt-in. Every approver is
`change.review`. The protected `rules` extent keeps its positive minimum,
authority class and mandatory patterns. Direct authors do not review their
own work. An authoring agent's controller may review an ordinary extent
only when `ownerMayReview` is true. Protected Rules retain controller
independence except for the existing declared single-controller exception.
That exception waives no required check.

This closes the implicit-zero and arbitrary-approver forms of October3.2.
Intentional zero review remains available and must be described as such.
A solo choice does not claim independent review or resistance to that
owner's key. Refusing all zero approvals would instead require a counted
reviewer other than the direct author; an authoring agent's controller could
meet an ordinary positive count only where owner review is allowed. Keeping
the historical permissive form would cost less integration but leave the
implicit and arbitrary-action forms open. Those alternatives are not the
selected new-family behavior.

Compose the complete certified Native policy, certificate/tree-verification
consumers and observation binding with the required-check union and every
protection of `68356c6c`. A decoder import or a higher cohort number alone
does not establish that composition. Commons keeps its separate Rules line;
the default still refuses reference fields as ruled. Retain bounded exact
fields, one catch-all, known check names, the protected Rules extent and
safe initial values. Before the first certified publish, configured is
false and Destination refuses `rules-not-configured`. Defaults provide
neither configuration nor a certificate. The contract applies to every
later publish. Its cost is coordinated Rules, Destination, Directory and
Register wiring, certificate evidence, caller compatibility and real
whole-family witnesses. No new administrator approval counter is added.

A person must state permission for an unmatched pattern in the input.
Neither solo mode, installation, an old policy, a catch-all nor an unknown
future tree supplies that permission. Tree verification retains the exact
existing explicit-future-permission rule. Witness unopted zero and another
action as approver refusing, explicit solo policy admitting, the protected
minimum surviving, and the exception preserving all checks.

### Recover kept work and fence a genuinely fresh attempt

The command keeps **no new secret and no new custody file**. The existing
configured signer stays in its existing location. No recovery seed, token,
password, private-key file, progress file or envelope file is introduced.
Public policy input bytes are input, not secret custody. If implementation
cannot meet this condition, report that before family source opens.

Recover progress from the room's verified entries. Match the signer, full
family references/incarnations, branch item, complete policy/proposal digest,
repository, ref and commit/tree binding. An ambiguous match stops; a changed
binding is not an automatic retry. When one request is kept, recover its
actual signed input and fact, follow only its selected certificate outcome
and retained proof, then finish or report its matching publication. Pending
stays pending and a kept refusal stays refused. A certificate for another
proposal, incarnation or binding cannot substitute. If publication is
already kept, report that fact and distinguish it from a later current
policy. Do not create another certification request to hide interruption,
refusal or unavailable evidence. Exact resubmission of a recovered kept
envelope retains its original identity and earlier receipt.

Before a request is kept, public entries cannot reveal the unrecorded
envelope's key, deadline or lost pre-admission result. Ruling `1f5e3077`
permits a **fresh semantic attempt**, not recovery or retry of that unknown
envelope, only under this fence:

1. Read one fresh authoritative Destination summary for the exact family
   incarnation, ready branch and repository binding. Fix its head `H` and
   branch revision `r` together.
2. Verify a complete contiguous, hash-linked history from genesis through
   exactly `H`, including its final hash and full scope references. Search
   that fixed prefix for the matching public operation identity. A later
   growing head does not change the prefix being proved.
3. Only if that verified prefix contains no matching kept request, sign the
   fresh certification request with `expected.on` fixed to `r`. Keep its
   envelope only in memory for that live attempt. Do not refresh its revision
   after an uncertain answer and sign another request.
4. Reconcile a lost/unavailable answer or revision refusal against verified
   public entries. Finish matching kept work, or report the actual changed
   binding, refusal, uncertainty or incomplete history. Do not claim the
   first unrecorded envelope's result.

A `Read.complete` flag alone proves no such absence: current history reads
may filter entries by reader authority while complete describes storage-page
exhaustion (`reads.ts:117–148,282–292`). A filtered gap, archive floor,
missing row/proof, hash or incarnation mismatch, forbidden read, or exhausted
read bound stops the absence proof. Read minima alone do not establish a
complete prefix (`client/handle.ts:42–60`). The command must report incomplete
history, not call it empty.

The current source argument is explicit: the certificate request is a branch
transition and always writes `rulesCertificateRequest`
(`destination-v14.ts:41–47,68–73`); Native checks the exact subject revision
before effects (`judge.ts:282–307`); folding the value effect touches and
increments the branch (`fold.ts:117–124,168–173`); judgment and sealing share
a transaction and recheck the head (`turn.ts:321–342`). An old in-flight
envelope fixed before the fresh summary has an expected revision no greater
than `r` in that incarnation. If both expect `r`, only one can be accepted.
If another act advances the branch, both may refuse. This is a source/design
argument, not proof about an unallocated new family: its exact definitions
and command must preserve and witness every premise after c+d.

The whole-family interruption matrix includes: stop before the room keeps
any request, then run command2 again and publish once; lost replies after
the request, certificate and publication are kept; and **both late-submit
orders**. If the old envelope commits first, the fresh envelope refuses its
fixed revision and reconciliation finishes the old kept request. If the
fresh envelope commits first, the old late envelope refuses. Retain offered
attempts separately from accepted requests and publications. Witness one
accepted request and one publication, unchanged fixed revision after an
uncertain answer, and no new secret/file. Also witness an unrelated revision
advance, terminal refusal, changed binding, ambiguous match and
filtered/archived/incomplete history. These outcomes need not complete a
publication; the command must say what it actually knows.

### Retain intentional open founding and the ruled administrator authority

Under `policy: "open"`, any signer may found. Ruling `11f4d825` retains this
behavior for the public Start register and leaves full October3.12 open by
choice. A founders list does not turn open into an allowlist. Use `policy:
"keys"` where that restriction is required. The new Register refuses the
misleading combination open plus nonempty founders; the install writer emits
`founders: []` under open and retains the operator founder under keys.
Historical retained install envelopes and signatures remain exact. Witness
another signer founding under open and refusing under keys. Do not report
the narrower input guard as full3.12 closure. Closing open entirely would
remove public self-service founding and require another enrollment or
installation design; that is not the chosen behavior. S1 owns the separate
public-founding windows; this section introduces no rate-limit mechanism.

November2.2 remains the stated governance fact: any one admin holds
`rules.publish` and can publish Rules alone, lowering thresholds outside the
fixed Rules-extent minimum. That minimum governs file landings, not the
publish act. A certificate proves policy and repository binding, not another
admin's approval. A second key requires counting/recovery design for a
one-admin room, parked by order `fc7576f8`. No new count, quorum or recovery
bypass enters this family.
